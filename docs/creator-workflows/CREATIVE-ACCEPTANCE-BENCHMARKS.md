# Creative acceptance benchmarks

Use the ordinary creator flow on FinalFrame Preview with the online development database. Begin each recipe from a short idea or an uploaded owned fixture. Let FinalFrame write the script and plan, then inspect the brief, route, estimate, accepted takes, timeline and downloaded MP4. Record the project, approved versions, job IDs, actual provider costs, and the downloaded file checksum.

Public videos are references for production technique. Use original characters, dialogue, footage, product UI, music and branding in the test assets.

## Advanced edits

- Hairstyle change. Use an authorized or synthetic subject. Verify the face, clothing, background and recorded voice persist while the hair changes.
- Vehicle or object swap. Change an original prop in an owned clip. Compare the movement and framing against the source. Judge hand contact and shadows.
- Motion transfer. Reproduce the timing and camera motion of an owned performance with a different character. Verify the provider honors the input clip.
- Masked edit. Check the unchanged regions before and after. A whole-frame redraw fails this test.
- Audio-driven portrait. Use owned speech, preserve the words and measure lip-sync drift.
- Provider clip continuation. Start from an accepted completed job. Check the join, subject and camera. An independent next scene can prove project continuity separately.
- Upscaling. Inspect the requested dimensions, original timing and retained audio.

[Higgsfield's Genjutsu workflow](https://higgsfield.ai/creator-hub/help-center/tools/how-do-i-use-genjutsu) distinguishes motion transfer from changing one element in place. Each requires separate evidence.

## Retest order

1. Reuse the existing two-scene pigeon visual assets. Replace the failed native dialogue with a locked, reviewed speech asset per line. Verify that the approved audio and captions survive the exported MP4. If mouth motion materially conflicts with the speech, use a validated audio-driven route or redesign the reaction shot around the line and record which approach was used.
2. Use the same project to prove the next-session continuation and selected-scene merge. Record the first approved version hash before and after.
3. Run the remaining recipes and edit operations against the matrix. Reuse approved output only where it tests the same requirement. Reconcile charges and outstanding holds before each new paid route. Retry a rejected route only after a concrete input or provider change.
4. Mark a recipe passing only after reviewing the downloaded result for all applicable quality criteria. Keep failed examples and the reason for the verdict.
