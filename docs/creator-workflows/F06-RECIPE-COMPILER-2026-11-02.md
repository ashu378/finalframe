# F06 isolated recipe compiler

Execution follow-up: see [F06 durable runner](F06-DURABLE-RUNNER-2026-11-02.md) for the separately flag-gated backend/UI wave. Pure compiler coverage alone is not a paid end-to-end acceptance claim.

The eight existing video types and starter briefs lead to canonical planning,
approval and individual durable jobs. Approval does not execute `plan.operations`.
Preparation, exact media selection, timeline composition, locking, manifests and
exports remain separate creator operations. The 19 retained records in
`/tmp/finalframe-complete-acceptance/export-probes.json` prove stored technical
exports; they do not establish eight ordinary prompt-to-download browser runs.

This packet adds only `src/lib/production/recipes/{contract,schema,compiler}.ts`
and pure tests. Nothing imports it into active planning, approvals, pages or
workers. There are no schema changes, external calls or scheduled jobs.

`finalframe.recipe` version 1 is a strict bounded authored AST. The compiler
accepts an independent canonical context: exact approved project/production
version and snapshot hash, frame rate, approved continuity binding, source
asset Storage/SHA/rights facts, approved shot references/explicit recipe slots,
and current voice consent. The future authenticated backend must build that
context from records, never accept these claims from a browser. The compiler
cannot itself establish session authority. Legacy approved plans stay manual.

Compilation produces a topologically ordered graph of reference preparation,
explicit generated or recorded narration, generation, four exact graphic templates, measured source ranges,
supplied music analysis, reviewed captions, timeline, manifest and export.
Generated assets, transcripts, takes, beat maps, caption plans and the exact
locked timeline require explicit owner approval receipts. A reference generated
later may bind only an explicit slot in the approved recipe/shot context; the
compiler cannot rewrite a frozen approved shot. Video references remain denied
without their own measured input billing certificate. Music uses supplied owned
audio, not an invented music-generation endpoint. Transcript of generated
narration must await asset approval and decoded measurement <=60 seconds; video
audio extraction needs a separate operation contract.

Each node has a request hash and deterministic idempotency key derived from
immutable recipe inputs, including canonical timing and source facts. Context
quote certificates bind the exact request hash. Missing, stale, mismatched or
zero paid ceilings produce an incomplete estimate with null totals. The future
server must derive conservative quote ceilings from existing reviewed catalogs,
including upper bounds for future outputs, and obtain fresh measured certificates
at actual submission. This preview is not a budget reservation or spending
permission. Only explicit opt-in after a complete estimate can activate a run.

The read-only resume helper observes existing exact jobs. Accepted or ambiguous
provider work is polled/reconciled, including after cancellation; it never becomes
a new purchase. Completed results are retained, while downstream approval remains
separate. Failed unaccepted work stops for explicit handling. Canonical approval
IDs/result bindings and cancellation must be re-resolved by the future runner.
Recorded narration is LOCAL: an approved measured same-project audio window, including a <=60-second window from a longer source. It carries no synthesis text, voice enrollment or provider quote, and cannot fall back to TTS. A future transcript adapter must resolve that exact selected window, never substitute the whole untrimmed recording. Approval-state changes are rechecked but do not rewrite byte-bound immutable identities.

Existing canonical review requirements remain mandatory before export; the
compiler does not approve a review or fabricate a completed artifact.

Next implementation dependencies are the root-owned persisted run/node schema,
authenticated canonical context/quote resolver, job adapters and approval-receipt
resolution, opt-in run UI and eight browser acceptance journeys. Narration must
be measured before placement; duration overflow requires revision. Captions need
validated timed segments or reviewed cues. D03 supplies beat analysis/correction;
F03 supplies longer assembly separately. Masks, exact performance transfer,
video-to-video lip sync and generated music/SFX stay outside this contract.

Verification: `node tests/recipes/run-recipe-compiler.cjs` exercises all eight
recipes and adverse schema/source/approval/quote/idempotency/recovery cases with
network forbidden. It does not generate media, mutate a database or certify
provider or creative acceptance.
