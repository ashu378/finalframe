## Supplied-audio Avatar certificate proposal

[HeyGen Audio to Video](https://developers.heygen.com/audio-to-video) explicitly makes video length follow supplied audio and supports an arbitrary single-person image. Its guide permits 30 minutes, whereas [Usage Limits](https://developers.heygen.com/docs/usage-limits) caps Avatar input audio at 600 seconds. Use the conservative intersection: audio-only WAV/MP3, measured duration greater than zero and at most 600 seconds, at most 32 MB. This is an application admission limit resolving conflicting documentation, not a claim that HeyGen publishes one consistent maximum. [Assets](https://developers.heygen.com/assets) limits URL images to 16 MB and URL audio to 32 MB; require JPEG/PNG portrait under 2K and within that smaller URL limit. The limits page documents 25 fps output.

Observed [OpenRouter video catalog](https://openrouter.ai/api/v1/videos/models): ID `heygen/avatar-iv`, canonical slug `heygen/avatar-iv-20260625`, SKU `duration_seconds=0.05`, output 720p/1080p, aspect ratios 16:9/9:16/1:1, null generation durations, no frame-image control. Provider endpoint tag is `heygen`. No minimum-charge rule was found in the reviewed OpenRouter sources; absence of one is not independent proof that no minimum exists. The generic model endpoint's zero prompt/completion prices are not video prices.

Proposed central reviewed contract `AVATAR_SUPPLIED_AUDIO_SOURCE_SECONDS_V1`: one approved portrait plus one approved measured recording; source audio determines full output length; bill `ceil(measured source seconds)` at the dedicated live SKU. Bind source project/asset/storage/checksum/byte size/probe facts and exact selected portrait, canonical model/version/provider, control and complete price fingerprints, quote time and contract version. Re-resolve at create, fence and fresh pre-POST worker check. Reject generation duration overrides, frames, video sources, TTS voice/script, generated audio, extra references and unsupported passthrough controls. Retain `KEEP_SOURCE`; a separate composition operation must implement muting.

The [HeyGen OpenAPI](https://developers.heygen.com/openapi/external-api.json) declares supplied `audio_url` mutually exclusive with script on `/v3/videos`; its docs name Avatar IV as the default engine. OpenRouter's dedicated catalog does not expose the upstream API version. This bridge/version correlation remains an explicit acceptance gate, along with technical output duration/audio checks and lip-sync inspection. A canonical slug alone cannot prove that upstream behavior.

## Seed reference-voice certificate proposal

[BytePlus Audio 1.0](https://docs.byteplus.com/en/docs/byteplusvoice/seedaudio-01), updated 12 October 2026, explicitly caps original output at 120 seconds and bills `original_duration`; delivered duration may differ after speed/postprocessing. It documents `seed-audio-1.0`, prompts at most 3000 characters, up to three reference clips, each at most 30 seconds/10 MB, and WAV/MP3/PCM/OGG Opus. These narrower upstream limits apply in addition to OpenRouter limits. Reference order determines numbered voices; these are not automatically multiple enrollment samples for one identity.

Observed [OpenRouter speech catalog](https://openrouter.ai/api/v1/models?output_modalities=speech): ID `bytedance-seed/seed-audio-1-0`, canonical slug `bytedance-seed/seed-audio-1-0-20260630`. The [Seed provider page](https://openrouter.ai/provider/seed) independently describes the 120-second limit and generated-audio-second billing. Current truncated model description is not sufficient dynamic authority and does not revoke the full primary contract.

Proposed reviewed central contract `SEED_AUDIO_ORIGINAL_SECONDS_120_V1`: reserve the full 120 original seconds, currently $0.30 before existing margin, regardless of requested narration duration or final playback speed. Require the exact reviewed model/version/provider and endpoint-wide price/control fingerprints; unknown versions, prices, endpoints or billing units fail closed. Replace the description regex with this explicit certificate, not an unbounded fallback. Submission/fence must revalidate the certificate and current approved, consented sample.

The [OpenRouter speech guide](https://openrouter.ai/docs/guides/overview/multimodal/tts) defines reference shapes, endpoint capabilities and placeholders. ## Performance transfer: supported references, missing exact operation

[Seedance 2.5](https://docs.byteplus.com/en/docs/ModelArk/seedance-2-5) and its [prompt guide](https://docs.byteplus.com/en/docs/modelark/seedance-2-5-prompt-guide) support reference-conditioned appearance/action/camera/audio. Explicit editing requires `role=reference_video`, `omni_reference_task_type=edit`, `ratio=adaptive`, and `duration=-1`; editing input is 4–30 seconds, and output can be 0.4 seconds shorter. Non-edit video references are 2–30 seconds, at most ten/30 seconds total, MP4/MOV H.264/H.265, at most 200 MB, 24–60 fps, dimensions 300–6000, ratio 0.4–2.5 and pixels 407696–8295044. Direct real-human-face references require the provider's portrait-registration workflow. The provider version is `dreamina-seedance-2-5-260628`.

OpenRouter currently observes canonical `bytedance/seedance-2.5-20260807`, 480p/720p, output 4–30 seconds, passthrough only `watermark`, `req_key`, `output_format`. Its [OpenAPI](https://openrouter.ai/openapi.json) has image/audio/video references, but no reference role/task; duration is positive and adaptive ratio is not enumerated. Do not smuggle unsupported keys. Semantic motion guidance is supported in principle; exact performance preservation, locked editing and provider portrait registration lack a documented portable bridge. Keep `PERFORMANCE_TRANSFER` denied until those controls and acceptance criteria are certified.

## Additional spend fence finding

[BytePlus pricing](https://docs.byteplus.com/en/docs/modelark/model-pricing), updated 23 October 2026, bills input-video generation from input plus output seconds, output dimensions and frame rate, divided by 1024. Video inputs also trigger a model/resolution/ratio/duration-specific minimum token charge. The linked official minimum table was inaccessible during this review, and the formula is explicitly an estimate rather than a hard maximum.

Review found that generic `estimateVideoCost` in `src/lib/ai/video-routing.ts` used output seconds only without selecting `video_tokens_with_video_input`, while `GENERATE` could accept video references. A coordinator-approved narrow fix now returns unknown cost for any video-input request outside the explicit measured edit/upscale contracts; continuation already rejects extra references. Route selection, canonical creation and the submission fence consequently deny uncertified video inputs. Already accepted jobs retain polling without re-purchase or reservation. A higher output rate alone cannot bound arbitrary source duration. Current Seedance 2.5 live video-input SKU is $0.0000064/token, versus $0.0000107 for output-only generation.

`tests/generation/run-video-input-billing-fence.cjs` exercises the current SKU and source-duration underquote, actual public action and canonical create before reservation, previously queued submission denial, and actual accepted-worker polling without discovery or resubmission. It uses isolated in-memory handlers and injected adapter seams. The reviewed minimum table and a defensible token upper bound remain required before enabling generic video-input generation.

## Regional workflow proposal: deterministic replacement composite

There is no portable OpenRouter mask field, and current FLUX Edit passthrough exposes only `safety_tolerance`. FinalFrame can implement a separate application workflow: render source `S`, aligned prompt-edited result `E`, and an explicitly authored mask `M` as `M*E + (1-M)*S`. This guarantees source pixels outside zero-alpha mask before encoding; lossy exported video does not preserve those pixels bit-for-bit. It provides regional replacement, not native generative inpainting or a promise that the model obeyed regional attention.

Existing renderer `types.ts`, `manifest.ts` and assembly planning have no mask asset/compositing contract; the existing `clipPath` is only a wipe transition. Shared design must define immutable project-bound source/edit/mask references and checksums, pixel grid/timebase/alignment, static versus tracked masks, frame coverage, feathering and inversion, explicit audio reuse, approval/version provenance, resource limits and render billing. Dynamic subjects need authored/tracked masks or rotoscoping. Reject missing frames, foreign/changed assets and mismatched time/dimensions. Test pre-encode outside-mask equality, moving boundaries, blend edges and source audio; inspect visual continuity with synthetic fixtures. Full-source FLUX cost still applies. No implementation is authorized without that shared contract discussion.
