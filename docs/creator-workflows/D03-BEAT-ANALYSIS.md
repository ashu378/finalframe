# D03 automatic beat analysis: local packet and rollout contract

This packet analyzes approved project audio with deterministic local media tools. It does not call a model, provider, payment, or email service. It creates immutable analysis versions and new timeline drafts; it never rewrites the analyzed asset, an earlier analysis version, or the source timeline. No deployment or online database write was performed for this packet.

## Flags and interfaces

Both flags default to false and remain coordinator controlled:

- `FINALFRAME_BEAT_ANALYSIS_ENABLED=true`: enables public request/manual/apply mutations and the authenticated renderer analysis route. Queries continue to expose retained versions while disabled.
- `FINALFRAME_BEAT_WORKER_ENABLED=true`: enables Convex scheduled analysis dispatch. Pausing retains queued work; `internal.beatAnalysis.wakePending` schedules at most 25 queued and 25 retrying jobs per invocation when both flags are enabled.

`api.beatAnalysis.request({projectId, assetId, idempotencyKey})` returns `{jobId, analysisVersionId?, replayed}`. `list({projectId,assetId})` returns actual server flags, `canEdit`, at most 30 jobs without lease/URL credentials, and at most 50 immutable versions. `manual({parentVersionId,beatsSeconds,correctionNote,idempotencyKey})` returns `{analysisVersionId,replayed}`. `retry` and `cancel` take `{jobId}`. All public writes require the current project owner/editor. Source approval, project/studio membership, actor status, canonical storage identity, rights and provenance are checked again at claim and completion. Explicit revoked memberships cannot fall through to legacy owner access.

`api.timelineEditor.previewBeatCuts({timelineId,analysisVersionId,audioClipId,pictureTrackId,beatIndices?})` returns the exact plan, FPS, source/analysis identity, and `planHash`. `applyBeatCuts` takes those fields plus `expectedPlanHash` and `idempotencyKey`, returning `{timelineId,operationId,replayed}`. It reauthorizes and recomputes the plan before replay or creation. Request, manual correction, and apply keys reject changed scope, user, or body.

The private renderer route is `POST /media/analyze-beats`, with the existing `x-finalframe-worker-secret` header. Request fields are `jobId`, `leaseId`, `projectId`, `assetId`, `storageId`, `sourceChecksum`, `assetChecksum`, `byteSize`, `algorithmVersion`, and a newly resolved canonical storage `url`. The bounded response echoes exact identity fields, omits `url`, and adds `{result,cached}`. The Convex action verifies every identity field before committing. Redirects are denied; media comes only from configured canonical Convex storage hosts. `/health` advertises the algorithm version and actual execution flag.

## Schema audit and version provenance

The coordinator owns the additive schema definitions and code generation. This packet uses exactly these approved tables:

- `beatAnalysisJobs`: project/asset/storage IDs, SHA-256 `sourceChecksum` from `_storage`, the asset's separate `assetChecksum`, algorithm version, request hash/key, saved actor, bounded attempts, exact expiring lease, scheduling/error/result references, and timestamps. Status is `QUEUED`, `PROCESSING`, `RETRYING`, `COMPLETED`, `FAILED`, or `CANCELED`. Indexes: `by_project`, `by_asset`, `by_idempotency`, `by_status`.
- `beatAnalysisVersions`: exact source IDs/checksums and algorithm; optional source job and parent version; `AUTO` or `MANUAL` origin; outcome, measured duration/sample rate, source-relative beat seconds, detector confidence, optional global tempo/tempo segments, reason, actor/time, and optional correction note. Optional `creationKey`/`requestHash` fence manual replay. Indexes: `by_project`, `by_asset`, `by_source`, `by_parent`, `by_creation_key`.

Runtime validation caps beats at 5,000 and tempo segments at 128; schema array validators alone are not treated as bounds. The algorithm is `ff-beat-spectral-flux-v1`. AUTO results can be `RELIABLE`, `AMBIGUOUS`, `SILENT`, or `NO_GRID`. Only reliable results expose automatic beat cuts. Variable tempo, irregular attacks, sustained tones, silence, and insufficient evidence never receive an invented reliable global grid. A manual map stores explicit reviewed times, parent lineage, and a required note, and retains the original detector confidence rather than assigning confidence 1. Its source must still match current authorized bytes.

The local detector uses positive log spectral flux, adaptive onset selection, autocorrelation, and observed-attack grid checks. Confidence is a heuristic diagnostic, not a calibrated probability or a guarantee for every musical genre. Method references: [Ellis beat tracking research](https://labrosa.ee.columbia.edu/projects/beattrack/) and [librosa onset strength documentation](https://librosa.org/doc/0.11.0/generated/librosa.onset.onset_strength.html). This implementation does not download or depend on those libraries at runtime.

## Resource and retry bounds

One shared admission gate spans queued/running rendering, media probes, and beat analysis in the existing isolated worker. It reserves capacity synchronously before acknowledgement or download. Media work receives 429 while any render is queued/running; render submissions receive 429 while probe/analysis owns the gate. Existing render concurrency, service CPU/RAM limits, and render queue size remain unchanged.

Per source: at most 64 MiB, ten minutes, and eight channels. Download is streamed with exact size and SHA-256 verification. Decode selects the first audio stream and uses one FFmpeg thread, mono 16 kHz float32 (at most 38.4 MB PCM), local `file,pipe` protocols, an output size guard, and a hard time guard. Download/probe/decode/thread caps are 30/15/45/60 seconds, within a shared 120-second deadline. The analysis thread additionally caps V8 old/young/stack space at 128/32/4 MiB; these are thread ceilings, not increased service allocations. Source/PCM temporary files are removed in `finally` after normal success or failure; operating-system cleanup of raw temporary directories after a hard process/host kill remains an operations responsibility.

Derived receipts use private 0700 directories and 0600 files, atomic rename after file fsync, exact source/version cache keys, and validation on replay. Normal receipts are capped at 256 KiB each, 128 entries, and 16 MiB total; oldest known derived entries are evictable, unlike authoritative Convex versions. Known incomplete derived receipts older than one hour are removed. Unfamiliar files or excessive recovery debris fail closed for administrator review. Reusing a receipt returns the incoming exact job/lease identity without re-downloading or recomputing audio. The cache is an optimization; loss can cause bounded recomputation without losing version history.

Convex holds a three-minute lease, at most three non-busy attempts, and a two-hour request window. Busy/paused worker responses retry after 30 seconds without consuming a processing attempt, within the same two-hour window. Expired leases can retry this deterministic analysis; duplicate or late results cannot complete a different/canceled lease. HTTP receipts are limited to 256 KiB and 130 seconds. Retry errors contain stable codes, not raw source URLs or credentials.

## Beat-cut boundaries and preservation

Automatic maps require reliable evidence; reviewed manual maps are explicit alternatives. Picture allocation uses a bounded `O(pictures × visible beats)` planner, two to 200 clips, supported FPS, and existing picture source handles. It trims existing approved ranges only; it never stretches, loops, extends, or silently duplicates footage. Optional explicit beat indices must be increasing and feasible. The selected soundtrack starts at timeline zero; its original trim maps source-relative beat times into timeline frames. Existing timeline authoring remains limited to 60 seconds even though source analysis accepts ten minutes.

Independent audio clip position, duration, source trim, gain and fades are retained. Picture timing changes create a new DRAFT and an `APPLY_BEAT_CUTS` operation containing source timeline, map/checksum, chosen beat boundaries and plan hash. Retained approved/locked source timelines remain unchanged. Current approved production lineage, source assets and shots are rechecked. Captions, non-cut transitions, unsupported source handles, too few feasible beats, and other clips extending past the selected soundtrack fail with an explicit explanation. They are not omitted or silently shortened. Native picture audio follows its corresponding trimmed picture; users must review speech before approving a new cut. This is frame-aligned picture editing, not a claim of sample-exact encoded audio duration.

## Verification and rollout

Local checks use original PCM/WAV click tracks, silence, sustained tones, leading silence/missing attacks, noisy grids, tempo changes and irregular timing. In-memory actual-handler tests cover lease/authorization/replay/cache/manual/apply behavior and mocked worker receipt failures. Real FFmpeg/thread/local HTTP tests block external fetch and verify checksum decode, cache, authentication, and mutual heavy-work exclusion. No online database or paid provider is involved.

Run `pnpm --dir renderer test`, `pnpm --dir renderer test:beats:media`, `node tests/production-edit/run-beat-analysis.cjs`, and `node tests/production-edit/run-finishing-v5.cjs`. Run app typecheck and targeted ESLint as listed in the packet handoff. A diagnostic ten-minute original 120 BPM click fixture produced 1,199 supported beats in about 2.3 seconds and about 72 MiB whole-process RSS on the local host; production timing and broad music correctness are not certified by that fixture.

Safe rollout order: coordinator schema/codegen and functions with flags false; worker readers/route and health with flag false; coordinator's fixture-only online source/lease/permission/worker-busy/manual/new-draft verification; then explicit feature enablement. No new service or provider purchase is needed. Production/browser creative acceptance and host-kill temporary-file cleanup verification remain coordinator checks. Persistent render output/state volume verification remains the independent renderer recovery gate.

Rollback: disable both beat flags first, retain all jobs/versions/operations and old timelines, and retain readable queries. Do not delete schema tables or reset usage/budget records. Running work may finish locally but exact source/lease/cancellation checks govern commit. After a pause, use the bounded wake operation to resume queued work; jobs beyond the two-hour window require a new request. Reverting worker code requires both flags false first so no dispatch targets an absent route. Manifest v5 writer gating and unrelated email/payment flags are unaffected.
